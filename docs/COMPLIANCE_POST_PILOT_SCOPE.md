# Post-Pilot Compliance Scope

**State:** DEFERRED DEPENDENCY REGISTER — NOT A ROADMAP COMMITMENT

| Trigger | Additional work before expansion | Primary route |
|---|---|---|
| New city/scale | Recheck support capacity, merchant evidence, incident response and retention | `PRODUCT_OWNER` |
| Sponsored ads | Final disclosure, claim, targeting, measurement, children and policy eligibility review | `LAWYER` + privacy |
| Behavioral personalization | Purpose/ground, transparency, objection, profiling and transfer review | privacy + lawyer |
| Economic rewards | Payment/e-money perimeter, funding, expiry, tax/accounting and customer terms | lawyer + accountant |
| Cross-merchant value | Closed-loop/payment-services analysis and settlement/accounting design | lawyer + accountant |
| Regulated categories | Product-by-product and merchant-capability authorization/evidence rules | domain specialist |
| Chat/media | Report, evidence access, retention, deletion and unlawful-content procedure | privacy + lawyer |
| Operator team | Role segregation, access review, training and audit sampling | technical architect |
| New vendors/countries | Controller/processor role, contract, subprocessor and transfer mechanism | privacy specialist |
| Advanced analytics | Cohort thresholds, raw-event retention, test-traffic separation and rights effects | privacy specialist |
| Automated moderation | Explainability, false-positive safeguards, appeal and human-review boundary | lawyer + owner |

Post-pilot expansion does not relax pilot controls. Each trigger opens only its own dependency lane;
unrelated modules should not be blocked.

# Badge Revocation

Status: **PROPOSED — OWNER/POLICY REVIEW REQUIRED**
Wave: 18 / Workstream AC

## Triggers

- Source fraud or verified-purchase correction invalidates evidence.
- Merchant/shop suspension or verification expiry affects a factual current badge.
- Catalog/taxonomy correction proves the achievement claim wrong.
- Bad data, duplicated event or rule implementation defect.
- Policy change prospectively or, only with explicit justification, retrospectively changes eligibility.

## Required process

1. Record restricted trigger evidence and scope.
2. Determine automatic, held-for-review or manual revocation class.
3. Append revoke/supersede event referencing award/rule version.
4. Recompute derived display without deleting history.
5. Notify with safe reason and appeal where appropriate.
6. Audit reinstatement/re-award separately.

## Trust rules

- Inactivity or ad non-participation is not revocation.
- Merchant cannot revoke customer badge or review-derived evidence.
- Customer cannot hide a merchant's factual suspension from other users.
- Security details remain restricted; public labels avoid unsupported accusation.
- Reward balance/review right changes only under their own systems.

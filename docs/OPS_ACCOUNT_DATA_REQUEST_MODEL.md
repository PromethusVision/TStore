# Account Data Request Operations

**State:** PROPOSED — PRIVACY/LEGAL/PRODUCT REVIEW REQUIRED

## Request families

- access/confirmation of processing;
- portable/exportable copy where applicable;
- correction of inaccurate profile/account data;
- deletion/account closure;
- restriction/objection/consent preference where applicable;
- explanation of retention or inability to delete;
- authorized representative or deceased/incapacitated-person request, subject to policy.

## Workflow

Secure intake → ownership/authority verification without password/OTP → request scope clarification → case and deadline/legal routing → discover systems/data categories → assess identity conflicts, legal holds, fraud/security evidence, transaction/audit obligations, and third-party data → execute approved actions server-authoritatively → independently reconcile → communicate result/exceptions → retain minimal request audit.

## System inventory candidates

Auth/identity, profile/consent, saved location/device-local behavior, chat/notifications, cart/wishlist, reviews, QR/verified purchase, merchant/shop/staff, catalog assertions/listings/media, ads/rewards if later enabled, cases/audit/security logs, Storage, backups and vendors.

## Deletion boundary

Account deletion is not blind cascading history erasure. Verified transactions, reviews, merchant/catalog provenance, fraud/security evidence, accounting/legal records, and other persons' rights may require deletion, anonymization, restriction, or retained minimal linkage under approved rules. Operators cannot choose ad hoc.

The [KVKK deletion/anonymization guidance](https://www.kvkk.gov.tr/Icerik/2038/kisisel-verilerin-silinmesi-yok-edilmesi-veya-anonim-hale-getirilmesi) emphasizes technical/administrative measures and making deleted data inaccessible/unusable when purpose ends.

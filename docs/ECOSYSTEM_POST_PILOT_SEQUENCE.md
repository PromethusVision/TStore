# Ecosystem Post-Pilot Sequence

**State:** RECOMMENDED ORDER — NO RUNTIME AUTHORIZATION

| Stage | System expansion | Evidence gate |
|---:|---|---|
| 1 | Full Merchant App core: membership, shop/listing, QR, action inbox | pilot verifier/listing workload and security evidence |
| 2 | Catalog governance: candidates, selected variants, correction lineage | actual duplicate/missing-product/domain needs |
| 3 | Merchant Taxonomy onboarding/runtime | owner-final hierarchy, policy evidence and organization/shop decision |
| 4 | Lean Ops case tooling and privacy/retention | manual queue volume, incident and appeal burden |
| 5 | Analytics/observability expansion | approved questions, consent/retention, data-quality baseline |
| 6 | Search/facet/legacy runtime reconciliation | stable IDs and migration acceptance |
| 7 | Ads shadow measurement | owner chooses Ads, exact listing eligibility, disclosure/policy/kill switch |
| 8 | Narrow non-auction Ads pilot | shadow reconciliation, merchant/customer trust and finance readiness |
| 9 | Factual merchant signals/internal reputation | sufficient verified-purchase/review/accuracy history and fairness review |
| 10 | Customer badges without levels/challenges | trusted evidence and dark-pattern/privacy acceptance |
| 11 | Reward shadow ledger | amount/quantity/funding/redemption/legal/accounting decisions |
| 12 | Controlled Reward pilot | fraud/dispute/reversal/expiry operations proven |

Ads, Reward and reputation are independently gated. Launching one does not justify
the others. Merchant App and core Ops evidence precede economic/trust expansion.

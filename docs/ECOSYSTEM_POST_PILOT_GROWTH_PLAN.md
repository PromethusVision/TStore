# Ads, Reward, Gamification and Reputation Post-Pilot Plan

**State:** RECOMMENDED SEQUENCE — NO FEATURE APPROVED

## Evidence-first sequence

1. Stabilize merchant membership, listing truth and QR operations.
2. Collect minimized pilot health evidence and resolve catalog/policy failures.
3. Add transparent merchant quality inputs; retain visible ratings independently.
4. If demand exists, run Ads in shadow/no-billing mode and validate separation.
5. Decide reward funding, authoritative amount/quantity and liability before promise.
6. Build immutable reward ledger/idempotency before any visible balance.
7. Consider factual badges after trusted event volume; do not launch levels/streaks by
   default.
8. Expand operations/analytics only in response to observed load or risk.

## Independent go/no-go gates

| System | Go evidence | Default if absent |
|---|---|---|
| Ads | organic value, eligible supply, billing/dispute decision | no Ads |
| Reward | trusted earning unit, funder, redemption and correction contract | no promise |
| Customer badges | meaningful trusted evidence and comprehension test | hidden/inactive |
| Reputation | sufficient history, explainability and cold-start fairness | ratings/counts only |
| Advanced Ops | sustained case volume/SLA need | manual controlled process |
| Advanced Analytics | named decision question and privacy budget | do not collect |

## Separation invariant

Ad delivery or spend cannot grant review eligibility, reward, badge or reputation.
Reward earning cannot alter review rights. Analytics observation cannot become an
authoritative domain event.

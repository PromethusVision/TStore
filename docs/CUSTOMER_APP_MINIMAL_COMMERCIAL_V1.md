# Customer App Minimal Commercial V1

Status: **ESENLER O2O PILOT DEFINITION**

| Class | Capabilities |
|---|---|
| MANDATORY | Safe startup/config; Auth/profile/consent; Home/category/search/nearby; product/seller/shop details; location permission handling; single-store Cart V2; opaque QR; verified purchase evidence; review eligibility; settings/account deletion; error/security/session isolation |
| VALUABLE | Wishlist, saved locations, product chat, in-app notifications, recent searches/viewed products, ratings/history surfaces |
| DEFERABLE | Postal addresses, push notifications, avatar upload, broad pagination before scale, crash provider if an explicit manual incident process is accepted for a very limited pilot |
| FUTURE | Online payment/shipping/checkout, advertising engine, rewards/gamification, generalized commerce orders, advanced personalization and Merchant analytics |

The pilot requires a merchant/verifier operating path even though it does not
require the full Merchant App. A controlled verifier tool/process may close the
pilot gate; public scale requires the merchant experience, catalog operations
and support processes.

Minimal V1 does not mean shipping the demo taxonomy or non-final visuals without
an owner decision. Those remain release-policy choices, not new customer-module
requirements.

# Reward Threshold Options

**State:** OPTIONS — OWNER DECISION REQUIRED

| Model | Example concept | Risk |
|---|---|---|
| Fixed purchase count | N settled verified events | Split-purchase/collusion; N remains TBD. |
| Fixed stamps | One validated stamp per eligible event | Stamp value and repeat rules TBD. |
| Tiered threshold | Multiple milestones | Complexity and loss-aversion pressure. |
| Merchant template | Bounded threshold choices | Inconsistent programs/support load. |
| No threshold | Immediate fixed benefit | Funding and fraud exposure. |

A threshold is versioned at enrollment/earning, never silently raised. Reversal can reduce derived progress through an auditable event, not a hidden balance edit. Near-threshold messaging needs opt-out/frequency caps. Numeric thresholds are intentionally not proposed here.

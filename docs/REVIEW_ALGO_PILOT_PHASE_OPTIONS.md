# Pilot Phase Options

**State:** PHASED RECOMMENDATION — OWNER DECISION REQUIRED

| Phase | Scope | Public reputation output | Gate |
|---|---|---|---|
| 1 | single form; structured data collection | none | comprehension, privacy, evidence/idempotency |
| 2 | internal aggregate/fairness/fraud analysis | none | sample quality and false-positive review |
| 3 | narrow primary badges | factual, explainable badges only | owner thresholds, operations/appeal, method notice |
| 4 | composite/meta badges | selected composite/local claims | stable data, cohort sufficiency, owner approval |

## Recommendation

Architecture can be built later, but the first Esenler pilot should start no further than **Phase 1**.
Merchant reputation is not required to validate QR purchases or product reviews. Run Phase 2 only after
enough synthetic and real-consented Development/pilot evidence exists. `Mahallenin Yıldızı` stays Phase 4.

## Pilot acceptance questions

- Do customers understand product versus shop scopes?
- Is three-question completion/quality acceptable versus four?
- Do repeat customers dominate raw submissions before capping?
- Are dimensions useful across merchant sectors?
- Can operations explain/correct evidence without editing scores?
- Are low-volume/new shops treated as insufficient history rather than low quality?

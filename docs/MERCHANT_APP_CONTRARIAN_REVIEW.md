# Merchant App Contrarian Review

Status: **RESEARCH CHALLENGE — OWNER REVIEW REQUIRED**
Wave: 17 / WP94

## Challenges

### Is a separate Merchant App needed?

A responsive web dashboard could lower install/support friction for catalog work. Counterpoint: frequent camera QR verification, staff device use and secure app context favor mobile. Validate actual scan frequency before final client decision.

### Is dashboard V1 necessary?

Action inbox plus four core tasks may outperform charts. Recommendation: dashboard is SHOULD, not a blocker except operational action-required visibility.

### Are roles premature?

Yes if pilot owners operate alone. Backend membership/capability boundaries are still necessary; UI staff management can activate later.

### Is stock management unrealistic?

Exact stock is unrealistic for many local merchants. Keep semantic availability/unknown and freshness; do not promise inventory sync.

### Is merchant taxonomy too complex?

Yes if exposed as a large tree. Use search-first, approved leaf selection; sector never controls product identity or role.

### Can catalog moderation scale?

Candidate/custom support may create the largest support queue. Launch categories/allowlist, duplicate prevention and operational ownership are prerequisites.

### Is QR awkward at checkout?

Two devices, camera permission and short TTL add friction. Do not weaken security; test placement, context density and regenerate UX physically.

### Is V1 still too large?

Yes if analytics, reviews, staff, media and multi-branch all become launch blockers. Protect the 16 core capabilities, treat the seven SHOULD items as removable pilot scope.

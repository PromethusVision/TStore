# Customer Gamification Display Model

Status: **PROPOSED — NO UI IMPLEMENTATION**
Wave: 18 / Workstream AF

## Candidate surfaces

| Surface | Appropriate content | Risk |
|---|---|---|
| Private profile | Reward progress, active badges and explanations | Lowest privacy risk |
| Activity/history | Earn/revoke/adjust events with safe summaries | Information overload |
| Review byline | Optional non-economic contribution badge | Purchase/profile inference and review bias |
| Public profile | Explicitly opted-in low-sensitivity badges only | Social pressure/social-credit perception |

## Display requirements

- Reward balance/progress, badge, level and merchant reputation are visually/semantically distinct.
- Every badge links to why earned, evidence class/window and what it does not imply.
- Revoked/retired history is private by default; no shame label.
- Zero/insufficient/pending/held/reversed states are not presented as failure of character.
- Dynamic text, screen-reader labels and no color-only meaning.

## Recommendation

Start private profile-only if badges are later approved. Review/public-profile display should remain deferred pending privacy/trust testing.

# Reward, Gamification and Reputation Contrarian Review

**State:** AGENT REVIEW — NOT OWNER APPROVED

## Conclusion first

The Esenler commercial pilot should not launch economic rewards, public customer gamification or a composite merchant reputation system. The pilot can validate the stronger foundation—discovery, merchant-confirmed physical purchases and independent verified reviews—without new liability or sparse-data trust claims.

## Challenges

| Question | Contrarian finding |
|---|---|
| Does the pilot need Reward Engine? | No. It does not improve proof of core marketplace demand enough to offset funding, reconciliation, policy and support risk. |
| Could reward complexity precede product-market fit? | Yes. Points/vouchers can create accounting, tax, contractual and operational obligations before merchant economics are known. |
| Could gamification cheapen local commerce? | Yes, if it converts neighborhood discovery into points/status pressure. Recognition must remain optional and evidence-based. |
| Are badges sufficient without levels? | If gamification is later justified, a few private explainable badges are enough to test value. |
| Are challenges useful? | Unproven. Discovery-only challenges might help later; spend-required challenges are inappropriate. |
| Are purchase streaks appropriate? | No recommendation to use them; they pressure purchase cadence and exploit loss aversion. |
| Does merchant reputation duplicate ratings? | A composite score likely would. Factual operational signals can complement—not obscure—rating/count. |
| Does reputation create cold-start harm? | Yes unless `insufficient history` replaces low trust and no ranking penalty is inferred. |
| Could rewards drive unnecessary spending? | Yes, especially thresholds, expiry countdowns and streaks. |
| Could merchant funding create disputes? | Yes: changing terms, insufficient funding, refund/reversal and branch scope. |
| Could platform-wide value become liability? | Yes; cross-merchant clearing and customer promises require mature operations. |
| Should rewards follow Merchant App and Ads? | Merchant App/verified evidence must precede reward. Ads may launch independently but cannot affect earning/reputation. |
| Could customer badges be postponed? | Yes, with almost no core pilot harm. |
| Is reputation useful before enough data? | No public rating-like score; shadow factual metrics can test coverage/fairness later. |

## Recommendation changes

Earlier option documents treated fixed stamps and private badges as safest *architectural candidates*. This contrarian pass sharpens timing: they are `POST_PILOT`, not pilot features. It does not change their relative safety if the owner later authorizes implementation.

## What remains valuable now

Preserve stable event/identity contracts, review/ads separations, policy fail-closed rules and an implementation-ready decision pack. Collect ordinary product metrics—not reward promises—in the pilot. Reassess only after merchant adoption, verified event volume, review quality and support capacity are measured.

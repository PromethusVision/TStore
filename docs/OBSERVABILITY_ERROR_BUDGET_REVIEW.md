# EsnaftaVar Error Budget Review

**State:** `RECOMMENDATION — DEFER FORMAL PROGRAM FOR PILOT`

Formal SLO/error budgets can help protect startup, auth and QR reliability once
traffic, ownership and response practice exist. At the Esenler pilot stage, a
full organization-wide budget program is likely overhead without trustworthy
baselines.

Recommended sequence:

1. define critical journeys and valid attempts;
2. instrument success/latency and data-integrity invariants;
3. collect a stable pilot baseline with test/demo excluded;
4. assign owners/runbooks;
5. trial one or two SLOs (for example QR server outcome and app startup);
6. adopt formal budgets only if they change release/priority decisions.

Never hide duplicate authoritative outcomes or security/privacy breaches inside
an error allowance. Exact objectives/windows and release policy remain owner/
engineering decisions.

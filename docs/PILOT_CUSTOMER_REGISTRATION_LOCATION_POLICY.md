# EsnaftaVar Esenler Pilot — Registration and Location Policy Options

**State:** `OWNER DECISIONS OPEN`

## Registration options

| Option | Benefit | Cost/risk | Agent recommendation |
|---|---|---|---|
| Login before any discovery | Simple identity funnel | High friction; hides guest value | Not recommended for first browse |
| Guest discovery, login for protected actions | Demonstrates value before identity | Requires careful guest/auth continuity | Recommended candidate |
| Invite/account-only pilot | Tight cohort and support control | Selection bias; weak public discovery evidence | Useful for earliest closed phase |

Protected actions include those whose existing authorization contract requires an
account. The pilot does not invent new access rights.

## Location options

| Option | Benefit | Cost/risk | Agent recommendation |
|---|---|---|---|
| Precise location required at startup | Fast nearby sorting | Unnecessary collection, denial/drop-off | Do not use by default |
| Contextual permission at nearby task | Purpose is understandable | More state/fallback handling | Recommended candidate |
| Manual launch-cell selection only | Lowest location data | Less precise relevance/directions | Required fallback; possible first phase |

No precise location history is needed for pilot analytics. Record permission and
coarse functional outcome only where approved; directions intent is not a visit.

## Owner gates

1. public guest discovery versus invite/account-only first cohort;
2. actions that trigger registration;
3. contextual location prompt timing and manual fallback;
4. retention/access basis for any coarse location analytics;
5. copy and acceptance threshold.

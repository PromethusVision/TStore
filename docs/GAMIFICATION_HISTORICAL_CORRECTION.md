# Gamification Historical Correction

Status: **PROPOSED — OWNER DECISIONS OPEN**
Wave: 18 / Workstream AQ

## Correction types

- Verified purchase corrected/reversed under its authoritative process.
- Duplicate source event or evaluator defect.
- Product merge/split/variant correction.
- Shop/merchant identity or branch correction.
- Review lifecycle correction.
- Badge/reward rule implementation error.

## Rules

- Append correction, adjustment, reverse or supersede event; never rewrite old event to look originally correct.
- Merge deduplicates logical progress via lineage; no re-award.
- Split maps only with deterministic snapshot evidence; ambiguity remains historical/TBD.
- Reward correction does not independently alter review right.
- Rating/review correction remains canonical review authority.
- Merchant reputation recomputes affected intervals and explains current state without hiding actual rating.
- Customer/merchant receives safe correction/dispute path.

Retroactive rule changes, successor eligibility and goodwill exceptions remain owner/policy decisions.
